## 1. 执行摘要

### 1.1 五架构一句话定位

| 架构 | 定位 |
|---|---|
| A 容器型 | 以 namespace+cgroups+seccomp 直接组装的最小执行环境：成本与密度最优，边界 = 宿主内核正确性本身 |
| B MicroVM 型 | 每任务一个独立 guest 内核的 microVM，以快照恢复为创建路径：边界不依赖宿主内核，代价是 KVM 宿主池与池化/快照管线 |
| C 安全容器型 | 不改容器体验、把共享内核换掉：C1 gVisor 用用户态第二内核（零透传），C2 Kata 用轻量 VM；分野在边界实现与宿主需求 |
| D Wasm 型 | 不是 OS 执行环境，而是细粒度能力授权的函数/插件层：只承接可枚举能力面的负载子集，与 A/B/C 是分层关系不是替代关系 |
| E 混合型 | 不是第六种隔离技术，而是组织架构：B 主干 + A/C 降档 + D 工具层 + 浏览器档，统一控制面与 egress/凭证/制品三平面 |

### 1.2 选型框架的判定方式

不设综合评分、不算总分、不排名次（02 报告 §1.5 已证计费单位 ≥7 种不可通约，综合分只会把 U 级证据洗成精确假象）。框架只做三件事：①17 个维度逐个给出严格定义、证据来源与不可比陷阱，判定用 强/中/弱/未知/不适用 + 证据指针；②权重不在框架层预设，由场景公开声明门槛维（一票否决）/一阶维/二阶维；③产品点名受 CSV confidence 约束——隔离为 U 的产品不得作高安全场景的边界推荐，C 级候选只能以候选身份出现。推测性判断全部编号登记（C-1…C-18），不混入事实。

## 3. 两份交付的关键设计判断清单

**A 型（容器）**
- 元数据/RFC1918 拒绝做成产品**硬编码默认**（借鉴 E2B `DeniedSandboxCIDRs`），明确反对 OpenSandbox 的运维配方制默认。
- seccomp/AppArmor profile 做成产品内建基线而非运维模板自选（对 04 现状的修正）。
- 终止语义 = 单元整体销毁（宿主侧枚举核验零残留），依据本项目 EXP-02 的 [SELF] 对照实证与冻结线 C4/C7 互锁。
- egress 用 per-sandbox sidecar 独占 NET_ADMIN；凭证走 Vault 出口注入且**不落盘**（带 Fast 路径明文文件的前车之鉴）。

**B 型（MicroVM）**
- **jailer 定为公有多租户默认开、自托管可关并记录理由**；且任何情况下不得把「没开 jailer」写成「没有 seccomp」（VMM 内建 seccomp 与 jailer 是两层独立机制，A 级上游事实）。
- **快照在平台侧做认证 + 加密 + 审计、按最高密级对待**——因为上游 CRC64 仅覆盖 vmstate 且非防篡改，快照文件在官方威胁模型里是可信输入，平台不补这一层就是把内存明文当普通文件管。
- 创建 = 快照恢复唯一路径（不设冷启直启分支）；恢复启用 VMGenID 且 guest 侧须做恢复后身份轮换（竞态窗口与 boot_id 不变是官方明示缺口）。
- 计量纪律：端到端 resume 与运行时恢复分段计时，容量规划禁止混用两类数字（62s 教训）。

**C 型（安全容器）**
- 平台层按宿主形态定版：云 VM 池默认 Systrap、裸金属才评估 KVM 平台（官方指引，非偏好问题）。
- 限额执行点钉在宿主 cgroup 包裹整个沙箱进程群，不指望沙箱内 cgroup（官方自列：只记账不限额）。
- Gofer 挂载导出范围 = 文件信任边界全集；directfs 默认关、开启走安全评审（以隔离换性能的旁路）。架构与审计口径按 LISAFS 写，9P 仅作历史沿革。
- 创建前兼容门：以目标负载 syscall 面对照官方兼容表先验核对，运行中 ENOSYS 失败归因为「兼容门漏检」回流创建服务。

**D 型（Wasm）**
- 负载子集边界是硬边界、先于一切设计：不能跑完整工具链是结构性事实，不是调优问题。
- imports 即权限清单：加载前静态审计、未授予的能力在实例化期即不存在；每加一个宿主函数按新增 syscall 的标准评审。
- 凭证不进组件内存（带凭证的调用由宿主函数在宿主侧完成）；高保障定版为宿主进程再入容器/MicroVM 的分层部署。

**E 型（混合）**
- 路由定版：不可信代码+完整工具链 → B 主干；内部批任务 → C1；高频短任务 → A 全硬化档；单工具/插件 → D；浏览器会话与桌面各成档（Chromium 跑在 B 或 A 单元内、CDP 只经带认证网关）。
- **故障不降档**：把 egress 的 fail-closed 原则推广到路由面——单档故障可改道同级或更高档，禁止自动降到更弱边界。
- 统一三平面：egress 策略一份、各档本地执行、每点过同一 C8 矩阵验收；凭证真值永不进任何档的沙箱；制品与快照库按档标注保真度，快照语义差异必须在 API 明示，禁止用统一词汇掩盖。
- 工作区制品是跨档迁移的唯一货币（导出/导入），不存在活迁移——源于 04「两套 checkpoint 互不共享」的实证教训。
