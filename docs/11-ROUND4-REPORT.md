## 3. 环境纠正专节：简报假设被实测证伪

Round 4 立项简报称本机"cgroup v2 可用、ip netns 可用"，据此设计了第一批实验。预注册前的环境探查实测**两项均不成立**（证据链在 10 报告 §0 与 raw/ 中），且后续实验又探明更深的干预层级：

| 简报假设 | 实测 [SELF] | 影响 |
|---|---|---|
| cgroup v2 可用（可建子组设配额） | 根 `cgroup.controllers` 为空；自建子组无 `cpu.max`/`memory.max`/`pids.max` 文件；向任意层级 `subtree_control` 写 `+cpu` 返回 ENOENT——**控制器未委派** | C1/C2/C3 的 cgroup 形式在本载体环境不具备，判定整体顺延 LAB-REF |
| systemd 瞬态单元可作配额执行体 | 探针三连：`CPUQuota=50%` 与 `20%` 下 3 s 忙循环实耗 CPU 均 ≈3.0 s；`TasksMax=16` 下成功派生 80 个子进程；`MemoryMax=64M` 下内存增长至 ≈3.1 GiB 未被杀——**瞬态单元只记属性、不执行** | systemd-run 路线禁用为配额载体；同时说明"属性可读回 ≠ 策略在执行"，是沙盒宿主审计的经典陷阱 |
| `ip netns` 可用 | `ip netns add`、`nsenter -t <pid> -n` 均 Operation not permitted；`unshare -n` 可用、按 PID 移交 veth 端点可用 | netns 单元改用 unshare 进程承载（EXP-02/04 已验证可行） |

另有 EXP-03 专项探针发现的**宿主 runtime 四层网络干预**（均为实测，非推测）：

1. **系统调用层拦截**：目标为 RFC1918/链路本地地址的 connect()/sendto() 立即返回 EPERM（宿主 shell、新建 user+net ns 内、单 ns 内均复现），先于一切 nft 规则——该环境自带 SSRF 式出口过滤；
2. **子 netns 数据面限制**：veth 双端 LOWER_UP、路由完整、route-get 正常，跨 ns 流量仍 ENETUNREACH、邻居表为空；子 ns 内实际可达的只有 TCP → 127/8；
3. **UDP 全面封锁**：sendto 对任何目标（含 127.0.0.1 任意端口）EPERM，DNS-over-UDP 在本载体不可用；
4. **nft conntrack 不可用**：任何 `ct state` 规则返回 ENOENT，状态防火墙在本载体无从谈起。

**这组证伪的独立价值**：它就是一份针对"沙盒宿主"本身的一手取证——研究用的这台 VM 并非中性裸机，而是一个被平台 runtime 施加了未委派 cgroup、属性-only 的 systemd 配额面、syscall 层出口过滤与受限数据面的沙盒环境。任何在此类宿主上做隔离实验的人，第一课都是先探明宿主给了什么、没给什么、以及哪些"可用"是假象。本项目将此作为 LAB-MINI 载体的常驻限定写入 09 §0/§2 与本节，后续引用本批数据必须连带此限定。

## 4. 近失事件披露（EXP-02 batch-2，不淡化）

事实：EXP-02 第 2 批运行中，驱动从 namespace 内部解析 `/proc/$$/status` 得到错误的 init 宿主 PID（ns 内外 PID 混用，解析落到宿主运行时进程），记录 `init_hostpid = 1` 并据此向 **PID 1** 发送了单次定向 SIGKILL。

后果：**宿主 systemd 未受影响、无数据损失**——内核对 PID namespace init 的信号保护在此起了作用；且全部 kill 均为单 PID 定向，没有其他进程被误杀。但必须写明：**无损是侥幸（内核保护兜底），不是设计**。在保护不适用的宿主上，同样的驱动错误可能杀死宿主 init，后果不可接受。

根因与修复（batch-3 先暴露了修复中的一处误判并崩溃、无数据产出，batch-4 为有效批）：

- init 宿主 PID 改由驱动在**宿主侧**以负载主进程的 ppid 推导，不再采信 ns 内 /proc 解析；
- **任何 kill 前强制断言**：拒绝 pid ≤ 10；init 命令行必须包含 `sleep infinity`；对照组主进程命令行必须包含 `exp02_workload.py`；主进程已死则登记跳过而非动手；
- pid 文件改原子写（tmp+rename）+ 解析重试；修复后先单轮冒烟验证全路径，再跑满 60 轮——有效批 60/60 轮完整、0 失败轮。

该事件与修复已同步登记在本机运维经验（AGENTS.md 实验室条目）中，作为后续所有杀进程类实验脚本的强制护栏来源。
