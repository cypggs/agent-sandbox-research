## 1. 任务一：威胁模型底稿（25 条）

### 1.0 方法：系统、资产、信任边界与攻击者模型

**被评测系统（通用参考形态，非某一产品）**：控制平面（API 网关、身份认证、调度器、镜像/模板仓库、快照存储、计费与审计）+ 数据平面（宿主机池、运行时：runc/gVisor/Kata/Firecracker/Wasmtime、guest 内 agent/executor、egress proxy、DNS 解析器、文件/卷服务、浏览器/GUI 会话服务）+ Agent Harness（LLM、工具注册表、MCP Server、凭证保管库）。

**核心资产**：宿主机与控制平面完整性；其他租户的代码/数据/凭证；本租户凭证与用户数据；云账号与内网服务；平台可用性与计费完整性；审计日志完整性。

**信任边界（编号供各条引用）**：

| 边界 | 两侧 | 说明 |
|---|---|---|
| TB-1 | 不可信输入（用户 prompt、网页、文件、仓库内容）→ LLM/Harness 决策 | 数据与指令不分离，是 Prompt Injection 的根源 |
| TB-2 | Harness/控制平面 → Sandbox 执行通道 | 工具参数在此从「文本」变成「命令/代码」 |
| TB-3 | Sandbox 内代码 → 宿主内核/VMM/Sentry/宿主函数 | 隔离强度主边界；容器共享宿主内核，MicroVM/Wasm 多一层独立边界 |
| TB-4 | Sandbox → 网络（公网/内网/元数据/其他租户） | egress、DNS、代理在此裁决 |
| TB-5 | Sandbox → 持久层（卷、快照、模板、缓存、日志） | 状态跨任务/跨租户存活的通道 |
| TB-6 | 租户 A → 租户 B（同宿主、同池、同存储、同浏览器集群） | 多租户边界，常由调度与清理而非隔离技术本身决定 |
| TB-7 | 供应链（镜像、依赖、模板、MCP Server、模型工具定义）→ 构建/运行期 | 代码在进沙箱前已被信任的环节 |
| TB-8 | 浏览器/GUI 会话 → 用户身份（Cookie、剪贴板、下载、上传） | 会话材料与本地资源在此交界 |

**攻击者模型（四档，后文「攻击前提」引用）**：
- **AM-1 任务内攻击者**：能向 Agent 提交任务/prompt，或控制 Agent 将读取的网页/文件/仓库（间接注入者）。
- **AM-2 代码执行攻击者**：已在沙箱内获得任意代码执行（这本就是沙箱的正常功能），目标是突破 TB-3/TB-4/TB-5/TB-6。**关键立场：沙箱内任意代码执行不是漏洞，是设计前提；评测的是它之后还能否越界。**
- **AM-3 恶意租户**：拥有合法账号/API Key，可创建沙箱、上传镜像/模板/快照、并发压测，目标跨租户或打平台。
- **AM-4 供应链攻击者**：能发布/劫持一个依赖包、镜像层、模板或 MCP Server，不直接拥有平台账号。

**统一字段**：每条按 攻击前提 / 攻击面 / 信任边界 / 影响 / 预防 / 检测 / 缓解与恢复 / 剩余风险 / 验证方法 九项给出。验证方法统一格式：假设 → 无害用例 → 通过判据（期望系统行为）。

### T01 恶意生成代码（Malicious Generated Code）

- **攻击前提**：AM-1/AM-2；LLM 生成的代码天然不可信，且生成过程可被任务内容影响；代码将在沙箱内以沙箱身份直接运行。
- **攻击面**：代码执行 API、Shell 工具、文件写入后执行、notebook/REPL、构建脚本（setup.py、npm scripts、Makefile 等自动执行钩子）。
- **信任边界**：TB-2、TB-3。
- **影响**：本身被设计为允许，影响取决于后续边界：读本任务文件、尝试联网、消耗资源、作为 T04/T09/T17 等的跳板；若执行通道在沙箱外（如 Harness 宿主机直接 eval），则直接等同宿主代码执行。
- **预防**：一切生成代码只在沙箱内执行、Harness 进程与执行进程分离且权限不互通；默认无网、无凭证、只读根文件系统 + 独立可写工作区；执行前静态扫描仅作辅助信号（不能作为边界）；禁止把生成代码拼进宿主侧解释器/模板引擎。
- **检测**：执行审计（命令、进程树、文件/网络事件与任务 ID 关联）；异常行为基线（首次出现外联、提权尝试、敏感路径访问）。
- **缓解与恢复**：单任务沙箱用后即毁；命中高危策略即冻结任务、保留取证快照、撤销该任务短期凭证。
- **剩余风险**：沙箱内行为空间仍很大（本任务数据可被毁、可在允许的网络范围内作恶）；「生成代码」与「正常代码」无可靠自动区分方法。
- **验证方法**（待执行）：在自建沙箱中让测试 Agent 生成并执行一段只写 canary 文件、只连自有回显域名的无害程序；判据：行为被完整审计、未触及工作区外与白名单外目标。证据等级：方法设计 C（待自测升 A）。

### T02 命令注入（Command Injection）

- **攻击前提**：AM-1；Harness/工具层把 LLM 输出或用户输入未经结构化处理拼入 Shell 命令、exec 参数或解释器字符串。
- **攻击面**：Shell 工具的命令拼接、文件名/路径参数、环境变量、git/curl 等子命令的参数注入（如以 `-` 开头的参数被当选项）、模板渲染。
- **信任边界**：TB-2（文本→命令的转换点）。
- **影响**：在执行通道所在权限域内获得预期外命令执行；若执行通道在沙箱外或带宿主凭证，危害放大至宿主/控制平面。
- **预防**：优先 argv 数组式 exec（不经 Shell）；必须用 Shell 时做严格引用/转义并用允许列表约束命令；参数与选项分离（`--` 终止符）；文件名规范化；工具层做结构化 schema 校验（对应 CWE-78 OS Command Injection，见 §1.27）。
- **检测**：命令审计中出现 Shell 元字符、多命令链、预期外二进制调用的告警；工具参数 schema 拒绝日志。
- **缓解与恢复**：同 T01；另需复查同批工具定义是否存在同类拼接点（注入往往是模式性缺陷而非单点）。
- **剩余风险**：业务确实需要自由 Shell 时，注入与合法用法不可分，只能靠 TB-3 兜底；参数注入（option injection）常被转义方案遗漏。
- **验证方法**（待执行）：向自建工具层提交含分号/管道/反引号/`--help` 型参数的无害探针（目标只是触碰 canary 文件）；判据：探针被当作数据而非命令、审计留痕、无 canary 触碰。证据等级：CWE-78 定义 A（CWE 官方）；本系统结论待自测。

### T03 任意代码执行通道滥用 / 沙箱语义逃逸

- **攻击前提**：AM-1/AM-2；平台除代码执行外还暴露了文件、浏览器、网络、包管理等多种工具，攻击者不突破隔离层，而是滥用「被允许的执行语义」本身（如通过包安装脚本、解释器调试接口、Jupyter 内核、语言运行时反射访问宿主注入的对象）。
- **攻击面**：语言运行时逃逸面（解释器沙箱如语言级限制的历史绕过）、REPL/内核协议、调试端口、平台注入到沙箱内的高权限 helper/SDK、挂载进沙箱的控制面 socket（如容器运行时 socket、云 SDK 凭证端点）。
- **信任边界**：TB-2、TB-3；本质是「边界画错位置」：危险能力被主动放进了边界内。
- **影响**：绕过本应存在的策略（网络、文件、凭证），严重时直达控制平面（如拿到运行时 socket 等同宿主 root 级控制，此为容器安全常识性结论，等级 B）。
- **预防**：沙箱内绝不挂载任何控制面 socket/凭证；注入的 helper 以最小权限独立进程运行且与用户代码不同 UID；语言级沙箱（分类 T8）不得单独作安全边界（沿用 01-TAXONOMY 判定）；调试/REPL 端口不对沙箱内代码开放或需独立认证。
- **检测**：沙箱内进程访问 helper 接口、socket 文件、非预期本地端口的审计告警；工具调用与进程行为交叉核对（有进程无对应工具记录 = 通道外执行）。
- **缓解与恢复**：下线问题 helper/通道、轮换可能经该通道触及的凭证、销毁相关模板重建。
- **剩余风险**：功能越丰富的沙箱注入面越大；第三方 SDK/helper 的权限常在集成时被默认放大。
- **验证方法**（待执行）：在自建环境枚举沙箱内可见的 socket、本地监听端口、环境变量、进程列表，逐项与「预期清单」 diff；判据：清单外能力为零。证据等级：方法 C，待自测。

### T04 容器逃逸（Container Escape）

- **攻击前提**：AM-2 且工作负载为普通容器（共享宿主内核）；需满足之一：危险配置（privileged、host namespace、危险 capability、宿主敏感目录挂载、运行时 socket 挂载）、运行时漏洞、或与内核漏洞组合（见 T08）。
- **攻击面**：runc/containerd 等运行时、`/proc` 与 `/sys` 暴露面、cgroup 接口、挂载点、capability 集合。公开先例（多源可查，等级 B，NVD 条目见 §1.27）：CVE-2019-5736（runc，恶意容器覆盖宿主 runc 二进制）、CVE-2024-21626（runc 文件描述符泄漏/工作目录问题致宿主文件系统访问，业界称 Leaky Vessels 家族之一）、CVE-2022-0492（cgroup release_agent 相关，特定配置下容器逃逸）。MITRE ATT&CK 将此类行为归为 T1611 Escape to Host（等级 A，ATT&CK 官方条目见 §1.27）。
- **信任边界**：TB-3（容器场景下该边界 = namespace/cgroup/seccomp/LSM 组合 + 共享内核，非硬件边界）。
- **影响**：宿主 root 级控制；进而全部同宿主租户、宿主上的云凭证、控制平面节点凭据失陷（影响半径 = 整台宿主及其调度信任）。
- **预防**：禁止 privileged 与 host namespace；cap drop ALL + 按需最小添加；`no-new-privileges`；只读根 + 掩蔽 `/proc`、`/sys` 敏感路径；seccomp 默认拒绝档案 + AppArmor/SELinux enforcing；user namespace / rootless 与 UID 映射；运行时与内核及时补丁（上列 CVE 均以补丁为根本修复）；高不可信等级负载改用 T3/T4 类隔离（MicroVM/安全容器）。
- **检测**：运行时安全监测（Falco/Tetragon 类 eBPF 检测：nsenter 使用、异常 mount、向宿主路径写入、capability 异常使用）；宿主完整性监测（运行时二进制哈希变化）。
- **缓解与恢复**：宿主一旦疑似逃逸成功，按整机失陷处置：摘除调度、取证、重镜像、轮换该机全部凭证，不做「只杀容器」的轻处置。
- **剩余风险**：共享内核决定了逃逸面随内核/运行时 CVE 持续再生；配置基线漂移（为排障临时开 privileged）是现实主因之一。
- **验证方法**（待执行）：仅在自建单机实验宿主上，用无害检测集（如公开的容器配置自检脚本/基线核查：capabilities、挂载、namespace、seccomp 状态枚举）验证基线；不运行公开 exploit；判据：基线检查全过、哨兵路径（宿主 canary 文件）从容器内不可见不可写。证据等级：CVE 事实 B（多家独立报道与厂商公告互证，本轮未逐条打开 NVD 原页，Round 2 应补 A 级核对）；基线自测待执行。

### T05 虚拟机 / MicroVM 逃逸（VM Escape）

- **攻击前提**：AM-2 且工作负载为 MicroVM/VM；需 VMM（如 Firecracker、Cloud Hypervisor、QEMU）设备模型、virtio 前后端、快照恢复代码或管理 API 存在漏洞，或 jailer/宿主侧加固缺失。
- **攻击面**：虚拟设备（net/block/vsock/balloon 等）、VMM 管理 API socket、快照加载解析、guest→host 共享机制。Firecracker 官方设计以「极小设备模型 + jailer（chroot/namespace/cgroup/seccomp/降权）包裹 VMM 进程」降低此面（等级 A，官方 design/jailer 文档见 §1.27）。
- **信任边界**：TB-3（此场景边界 = KVM 硬件虚拟化 + VMM；jailer 是第二道防线）。
- **影响**：逃逸成功一般先落入被 jailer 限制的 VMM 进程上下文，再需二次突破才达宿主；最坏情形同 T04。
- **预防**：VMM 最小设备集、禁用不需要的设备；VMM 进程必须经 jailer 类包裹（独立 UID、chroot、seccomp、cgroup）；管理 API socket 仅控制平面可达、guest 不可达；快照文件按不可信输入处理（见 T23）；VMM 补丁管理。
- **检测**：VMM 进程异常系统调用/崩溃、jailer 违规日志、guest 异常设备访问模式；宿主侧对 VMM 进程的资源与行为基线。
- **缓解与恢复**：按潜在宿主失陷预案处置（同 T04，但可结合 jailer 日志评估是否出第二道防线）；全量升级 VMM 版本。
- **剩余风险**：virtio 与快照解析是长期审计重点；设备越丰富（GPU 直通、共享文件系统）逃逸面越大；本轮未引用具体 VMM 逃逸 CVE 编号——无经核实者，标**未验证**，Round 2 如需引用必须先查官方安全公告原文。
- **验证方法**（待执行）：自建 Firecracker 环境中核查 jailer 实际生效（进程 UID、chroot、seccomp 状态、cgroup 归属逐项与官方 prod-host-setup 清单对照）；guest 内仅做无害设备枚举；判据：加固清单全项生效。证据等级：A（官方文档对照）+ 待自测。

### T06 安全容器 / Wasm / 语言级沙箱逃逸

- **攻击前提**：AM-2 且工作负载为 gVisor（Sentry）、Wasmtime 或语言级沙箱；需其拦截层实现漏洞，或宿主函数（host function / WASI 接口 / Gofer）授权过宽。
- **攻击面**：gVisor 的 Sentry 系统调用实现与其对宿主的少量系统调用、Gofer 文件协议；Wasmtime 的线性内存边界、导入函数、WASI preopen 目录与网络授权。官方立场（等级 A）：gVisor 架构文档称应用系统调用由用户态 Sentry 实现而非直达宿主内核；Wasmtime 安全文档称 Wasm 实例只能通过显式导入与外界交互、无原始系统调用访问（见 §1.27）。
- **信任边界**：TB-3（拦截层实现即边界；宿主函数是边界上的「门」，门的设计错误等同开洞）。
- **影响**：突破拦截层后落点取决于其宿主侧收敛程度（Sentry 自身被 seccomp/namespace 约束、Wasm 宿主进程权限），设计良好时影响小于直接宿主执行，设计不良时等同 T04。
- **预防**：拦截层保持官方默认收敛配置（Sentry 的 seccomp、Gofer 独立进程）；WASI 只 preopen 必要目录、默认不给网络与时钟外能力；宿主函数逐个做参数校验与权限判定、视为安全关键代码评审；版本跟踪官方安全公告。
- **检测**：拦截层崩溃/异常退出、宿主函数调用审计（参数范围、频率）、guest 试图访问未授权 preopen 外路径的拒绝日志。
- **缓解与恢复**：升级运行时、收紧宿主函数授权、销毁受影响环境；若宿主进程权限过高，先降权再谈其他。
- **剩余风险**：兼容性实现面积大（完整 syscall/WASI 语义），长尾漏洞不可避免；语言级沙箱（T8）历史绕过频繁，不得单独承载不可信代码（与 taxonomy 一致）。
- **验证方法**（待执行）：自建环境中以无害用例验证能力收敛：Wasm 模块尝试读 preopen 外的哨兵文件、gVisor 容器内核查可见宿主信息面；判据：全部被拒且留痕。证据等级：官方机制 A；本系统自测待执行。本轮不引用任何具体 gVisor/Wasmtime 逃逸 CVE 编号（检索中出现的个别 2026 年编号未经官方公告核实，标**未验证**，不写入结论）。

### T07 提权攻击（沙箱内 / Guest 内提权）

- **攻击前提**：AM-2 已有沙箱内低权代码执行；环境内存在 setuid 二进制、sudo 规则、过宽 capability、guest 内核漏洞或可写的高权限服务。
- **攻击面**：guest/容器内权限模型：UID 0 映射方式（容器 root 是否等于宿主 root 取决于 user namespace 配置）、file capabilities、cron/服务脚本、包管理器钩子。
- **信任边界**：TB-3 的内侧分层（沙箱内也应有最小权限，而非「进了沙箱就全是 root 无所谓」）。
- **影响**：沙箱内提权本身不等于逃逸，但会解锁逃逸前置条件（许多逃逸利用需要容器内 root）、扩大本任务数据与凭证的访问面、便于部署持久化子进程（T21）。
- **预防**：以非 root 用户运行工作负载；镜像内清除不必要 setuid 位与 sudo；cap drop 与 `no-new-privileges`；guest 镜像最小化；user namespace 使容器 root 映射为宿主非特权 UID。
- **检测**：UID 切换、setuid 执行、/etc/passwd 与 sudoers 变更、capability 使用审计。
- **缓解与恢复**：重建镜像基线、销毁环境；复查提权路径是否同时构成 T04 前置并升级处置等级。
- **剩余风险**：为兼容性保留的 root 需求（装包、改系统配置）与最小权限长期冲突；guest 内核提权面随镜像老化增长。
- **验证方法**（待执行）：自建镜像上运行权限基线枚举（setuid 清单、capabilities、sudo 规则）与基线 diff；以普通用户尝试读哨兵 root-only 文件；判据：基线无漂移、哨兵不可读。证据等级：方法 C，待自测。

### T08 内核漏洞利用（宿主 / Guest 内核）

- **攻击前提**：AM-2；宿主（容器场景）或 guest（VM 场景，影响较小）内核存在可达漏洞，且攻击面未被 seccomp/设备收敛挡住（如特定子系统、io_uring、eBPF、netfilter 等）。
- **攻击面**：全部可达系统调用与内核子系统。公开先例（等级 B，多源可查）：CVE-2016-5195（Dirty COW，写时复制竞态）、CVE-2022-0847（Dirty Pipe，管道缓冲区标志问题致只读文件页缓存可写）——两者说明「namespace 配置正确」不能替代内核补丁。本轮未逐条核对 NVD 原页，Round 2 补 A 级核对；除此二者外不引用其他内核 CVE 编号。
- **信任边界**：TB-3；容器共享宿主内核使该条对容器路线是结构性风险，对 MicroVM 路线则主要剩 guest 内核（逃逸还需再过 VMM）。
- **影响**：宿主内核沦陷 = 宿主全部隔离机制失效，影响同 T04 最坏情形。
- **预防**：内核版本与补丁 SLA；seccomp 收敛可达 syscall 集、禁用高风险子系统（如非必要禁用 unprivileged eBPF、限制 io_uring）；不可信等级最高的负载不放共享内核路线；gVisor 路线以 Sentry 拦截减少直达宿主内核的调用面（机制见 T06）。
- **检测**：内核崩溃/oops、异常 syscall 模式、运行时安全工具的内核利用行为特征；宿主内核版本与公告的持续比对（资产侧检测）。
- **缓解与恢复**：整机摘除、内核升级、按宿主失陷处置；事后复盘该漏洞可达性（当时 seccomp/配置是否本可挡住）。
- **剩余风险**：0day 不可消除，只能靠分层（隔离路线选择 + syscall 收敛 + 快速补丁）压缩概率与半径。
- **验证方法**（待执行）：自建宿主上做「可达面盘点」：以沙箱内无害程序枚举可调用 syscall 与目标子系统可用性，与策略清单对照；**不运行任何内核 exploit/PoC**；判据：高风险子系统按策略不可达、内核版本在补丁基线内。证据等级：方法 C。

### T09 SSRF（服务端请求伪造，经 Agent/沙箱出站）

- **攻击前提**：AM-1/AM-2；Agent 或沙箱内代码能发起 HTTP/网络请求且目标可被任务内容影响（抓取 URL、浏览器导航、webhook、包下载等均为天然入口）。
- **攻击面**：一切出站请求发起点；重定向跟随、URL 解析差异（userinfo、@、十进制/八进制 IP、0.0.0.0、短地址）、协议走私（file/gopher 等非 HTTP scheme，视客户端而定）。分类对应 CWE-918（等级 A，CWE 官方，见 §1.27），防护框架可参 OWASP SSRF Prevention Cheat Sheet（等级 A/B，OWASP 官方速查表，见 §1.27）。
- **信任边界**：TB-4。
- **影响**：以平台网络身份访问内网服务、元数据（T10）、其他租户服务、管理接口；或对外作攻击跳板（平台出口 IP 声誉与法律风险）。
- **预防**：默认拒绝出站 + 域名/IP 允许列表；统一 egress proxy 做 DNS 解析后校验与重定向逐跳复检；禁止请求落入私网/链路本地/回环地址段（除非显式业务白名单）；禁用危险 scheme；浏览器与代码执行共用同一 egress 策略（不能只防一侧）。
- **检测**：egress proxy 全量日志（目标、解析 IP、状态）；对解析到保留地址段的请求单独告警（被拒也告警，说明有人在试）。
- **缓解与恢复**：封禁任务与租户出口、复查同租户历史出站日志找已达成的内网访问、轮换可能被读到的内部凭据。
- **剩余风险**：允许列表业务（任意网页抓取）与 SSRF 防护天然冲突：开放抓取场景只能靠「解析后校验 + 沙箱网络与内网物理隔离」兜底，允许列表做不到。
- **验证方法**（待执行）：自建内网放置无害回显哨兵服务（仅返回 canary 文本），从沙箱以 IP 直连、域名解析、重定向跳转、十进制 IP 等变形方式尝试访问；判据：全部被 proxy/网络层拒绝并告警。证据等级：方法 C，待自测；CWE/OWASP 框架 A/B。

### T10 云实例元数据访问（IMDS / Metadata Service）

- **攻击前提**：AM-2 + T09 任一可达，或沙箱网络未屏蔽链路本地元数据地址；宿主/节点自身挂有云角色凭证。
- **攻击面**：云厂商元数据地址（AWS 为 169.254.169.254 及 IPv6 fd00:ec2::254，等级 A，AWS 官方文档见 §1.27；其他云有各自地址，本文不逐一列举以免误引）；容器场景还包括节点上的 kubelet/云 SDK 端点。
- **信任边界**：TB-4 中最具体的一条线：元数据服务按「网络可达即授权」设计，与沙箱的多租户假设直接冲突。
- **影响**：获取节点云角色临时凭证 → 以该角色权限调用云 API（读存储、启实例、改网络），影响跳出单台宿主进入云账号层。
- **预防**：沙箱网络命名空间内显式 DROP 元数据地址（IPv4+IPv6+域名形态）；AWS 侧启用 IMDSv2 required 并将 hop limit 设为不允许容器转发的值（官方机制，等级 A）；节点角色最小权限、能不用节点角色就不用；K8s 场景屏蔽云元数据并按 Pod 分发工作负载身份而非节点身份。
- **检测**：对元数据地址的任何来自沙箱网段的请求尝试即告警（正常业务永不应出现）；云审计中节点角色在异常时间/来源的 API 调用。
- **缓解与恢复**：立即失效/轮换节点角色会话、云侧审计该凭证全部调用、逐项回收其创建/修改的资源。
- **剩余风险**：新型元数据面（IPv6、其他链路本地服务、宿主上的本地代理端点）易被规则遗漏；hop limit 与容器网络模式（host network）冲突时 IMDSv2 的保护会被绕开。
- **验证方法**（待执行）：在自有云测试账号的自建节点上，从沙箱内尝试 IMDSv1 式 GET 与 IMDSv2 式 PUT/GET（目标仅为本机 instance-id 等无害字段）；判据：沙箱侧全部不可达/被拒、宿主侧正常、尝试被告警。证据等级：机制 A（AWS 官方文档）；本系统自测待执行。

### T11 内网扫描与横向移动

- **攻击前提**：AM-2；沙箱与内网/VPC/同宿主服务之间网络可达（哪怕仅部分端口），或能经 DNS/代理间接探测。
- **攻击面**：内网地址空间、宿主上的本地服务端口（agent、监控、调试、运行时 API）、同 VPC 微服务、K8s Service 网络。
- **信任边界**：TB-4、TB-6。
- **影响**：摸清内网拓扑与脆弱服务，为 T09/T10/T17 提供目标；未认证内网服务（现实中大量存在）被直接利用。
- **预防**：沙箱网段独立且默认与内网不通，需要访问的业务内网目标逐个白名单（经 egress proxy 以域名+端口粒度放行）；宿主本地服务不监听 0.0.0.0 或加本地认证；微隔离/安全组默认拒绝东西向。
- **检测**：单位时间连接目标数/失败率异常、SYN 扫描特征、NetFlow 中沙箱网段的横向连接基线偏离。
- **缓解与恢复**：隔离该沙箱网段、排查被探测到的内网服务是否已被利用、收紧白名单。
- **剩余风险**：经允许的 egress 通道（代理、DNS）仍可做低速探测与拓扑推断，只能限速与监测，不能根除。
- **验证方法**（待执行）：自建实验网段放哨兵主机（多端口假监听、只记录不响应真实服务），从沙箱做小范围连通性探测；判据：哨兵零连接到达、平台侧产生扫描告警。证据等级：方法 C。

### T12 DNS 绕过 / Rebinding / DNS 隧道

- **攻击前提**：AM-1/AM-2；平台在「域名允许」层做校验，但解析环节（解析器位置、缓存、TTL、重绑定）或 DNS 通道本身（任意出站 DNS 查询）未受控。
- **攻击面**：沙箱自带解析 vs proxy 解析的不一致（TOCTOU：校验时解析为公网、连接时重绑定为内网）、DNS rebinding、经 TXT/长子域名的数据外带（DNS tunneling）、DoH/DoT 绕过本地解析管控。
- **信任边界**：TB-4（DNS 是该边界最常被当作「不是数据通道」的盲区）。
- **影响**：绕过域名白名单与 SSRF 校验（放大 T09/T10）；低速但稳定的数据外带与 C2 通道（放大 T17）。
- **预防**：强制沙箱只用平台解析器（出站 53/853 及已知 DoH 端点默认拒绝或劫持至受控解析）；解析与连接同点执行（proxy 解析后以 IP 连接并绑定校验结果）；连接时复检最终 IP 的地址段；限制查询速率与子域名长度/熵异常监测。
- **检测**：DNS 查询日志（量、子域长度、TXT 查询占比、NXDOMAIN 率）；同一域名短时解析结果跳变（公网↔私网）告警。
- **缓解与恢复**：切断该任务 DNS 出口、回溯查询日志评估外带范围、封禁相关域名并复查同租户样本。
- **剩余风险**：合法业务域名下的 rebinding 需要连接层复检才能挡，纯 DNS 层防不住；经允许域名的前置代理（domain fronting 类手法）属更深议题，本轮标 C 待专研。
- **验证方法**（待执行）：自建权威 DNS 控制一个测试域名，使其先后解析到自有公网哨兵与内网哨兵（rebinding 模拟），并构造长子域名查询；判据：连接层拒绝内网结果、异常查询被记录告警。证据等级：方法 C。

### T13 恶意依赖包（Malicious Dependency）

- **攻击前提**：AM-4（或 AM-1 诱导 Agent 安装）；任务在沙箱内安装第三方包（pip/npm 等），包或其版本被投毒、typosquatting、依赖混淆（dependency confusion）或维护者账号被劫持。
- **攻击面**：包仓库解析、私有/公共源优先级、安装期脚本（postinstall/setup）、构建期执行、Agent「自动装包补环境」的默认行为。
- **信任边界**：TB-7 → 运行期经 TB-3 兜底（包代码在沙箱内执行本身合法，危险的是其携带的凭证访问与外联企图）。
- **影响**：沙箱内数据/凭证窃取（组合 T17）、挖矿（T22）、把投毒产物写入用户工作区/构建产物（污染向下游传播，见 T14）。
- **预防**：锁定文件 + 哈希校验（lockfile with integrity）；私有源优先与依赖混淆防护配置；安装在无网/无凭证的独立构建阶段、运行阶段只消费产物；新依赖引入需经仓库代理的缓存与扫描；对应 OWASP LLM03:2025 Supply Chain 的治理思路（等级 A/B，见 §1.27）。
- **检测**：安装期进程行为（装包进程发起外联、读工作区外文件）告警；依赖变更 diff 审计；已知恶意包情报比对（OSV 等公开漏洞/恶意包数据库，等级 B）。
- **缓解与恢复**：销毁环境、按 lockfile 回溯受影响任务、轮换任务凭证、把问题包加入代理黑名单。
- **剩余风险**：0day 投毒与「功能正常但留后门」的包无法靠扫描可靠识别；沙箱隔离只能限制半径，不能判定包的善恶。
- **验证方法**（待执行）：自建「无害恶意包」——本地私有源发布一个仅在安装期尝试写 canary 并连接自有回显服务的测试包，在自建沙箱安装；判据：安装期外联被拒/告警、canary 未出现在预期外位置、行为完整留痕。证据等级：方法 C。

### T14 供应链攻击（镜像 / 模板 / 构建 / MCP 与工具供应链）

- **攻击前提**：AM-4/AM-3；平台消费外部基础镜像、社区模板、预构建快照、MCP Server、工具定义或模型插件，且来源校验、签名或版本固定缺失。
- **攻击面**：镜像仓库（tag 可变性）、模板市场、构建缓存、CI 流水线、MCP Server 进程（常在沙箱外以 Harness 权限运行，是高价值目标）、工具描述本身（工具定义投毒诱导 LLM 误用，归入 TB-1/TB-7 交叉面）。
- **信任边界**：TB-7；MCP/工具层还跨 TB-2（其权限常高于沙箱内代码）。
- **影响**：一次投毒影响全部使用该镜像/模板/MCP 的租户；MCP Server 失陷可直接等于 Harness 权限失陷（凭证、跨租户工具访问）。
- **预防**：镜像按 digest 固定、签名验证（如 Sigstore/cosign 类机制，等级 B）、来源允许列表；模板/快照视为代码评审；MCP Server 沙箱化运行 + 逐工具最小权限 + 工具定义变更审计；构建与运行分离、构建缓存按租户隔离。
- **检测**：镜像/模板 digest 变更告警、SBOM diff、MCP 工具定义变更与异常工具调用序列审计。
- **缓解与恢复**：下架问题制品、全量重建受影响环境、按 SBOM 圈定影响租户并通知、轮换经 MCP 可达的凭证。
- **剩余风险**：签名只证明来源不证明无恶意；上游维护者账号劫持时「合法签名的新版本」仍可投毒，需版本升级的人工/策略闸门。
- **验证方法**（待执行）：自建仓库故意以同 tag 推送不同 digest 的无害镜像，验证平台是否拒绝/告警（digest 固定生效性）；对测试 MCP Server 做工具定义变更，验证审计是否记录；判据：两项均被检出。证据等级：方法 C。

### T15 文件系统越权与路径穿越

- **攻击前提**：AM-1/AM-2；文件工具/API 接受路径参数，或沙箱内代码处理符号链接、归档解压（tar/zip 的 `../` 与 symlink 条目，业界称 Zip Slip 类问题）、挂载点配置不当。
- **攻击面**：文件读写工具的路径规范化、共享工作区/卷挂载、OverlayFS 上层、`/proc` 与 `/sys`、宿主目录误挂载、解压与同步（上传/下载）功能。
- **信任边界**：TB-5、TB-3；对应 CWE-22 Path Traversal（等级 A，CWE 官方，见 §1.27）。
- **影响**：读写工作区外文件（其他租户卷、宿主文件、平台配置与凭证文件），或以符号链接竞态（TOCTOU）在检查后替换目标。
- **预防**：路径规范化后做前缀校验且在打开时用防穿越机制（如 openat2 的 `RESOLVE_BENEATH` 类语义，等级 B）；解压逐条目校验并拒绝绝对路径/外指 symlink；挂载最小化 + 只读默认；工作区按任务/租户独立目录与 UID；不跟随指向工作区外的 symlink。
- **检测**：文件工具拒绝日志（穿越尝试本身即信号）、沙箱内对工作区外哨兵文件的访问尝试（audit/eBPF）。
- **缓解与恢复**：封禁任务、核查哨兵与敏感文件访问记录、轮换可能被读的密钥、修复规范化逻辑后做回归用例。
- **剩余风险**：TOCTOU 竞态在「检查-打开」分离的实现里难以根除，必须靠打开时约束而非事前检查；硬链接、bind mount 等边角语义常被遗漏。
- **验证方法**（待执行）：自建文件工具前投喂 `../`、绝对路径、编码变形、含外指 symlink 的测试压缩包（目标仅为工作区外 canary 文件）；判据：全部被拒、canary 未被读/改、拒绝留痕。证据等级：CWE 定义 A；本系统自测待执行。

### T16 跨租户数据泄露（Cross-Tenant Leakage）

- **攻击前提**：AM-3/AM-2；多租户共享宿主、池、存储、缓存、浏览器集群或日志系统任一环节的隔离/清理/授权出错。
- **攻击面**：环境复用残留（T24）、共享缓存/对象存储的键命名与授权、日志与追踪系统里的跨租户可见性、调度把 A 的卷/快照挂给 B、侧信道（见剩余风险）。
- **信任边界**：TB-6（实现上横跨 TB-3/TB-5 与控制平面授权）。
- **影响**：租户间代码、数据、凭证、会话材料泄露；合规与信任级事故（对 SaaS 是生存级事件）。
- **预防**：租户维度贯穿全栈（调度、存储键、网络、日志索引都带 tenant ID 并在服务端强制校验，不信任客户端自报）；资源不跨租户复用或复用前经可验证擦除（T24）；对象存储逐对象授权；平台运维访问租户数据需审计与最小化。
- **检测**：跨租户 canary 巡检（每租户植入唯一哨兵、定期跨界探测）；授权拒绝日志；数据访问审计的租户一致性自动核对。
- **缓解与恢复**：立即隔离受影响资源池、圈定时间窗与对象范围、按合规流程通知受影响租户、轮换涉事凭证。
- **剩余风险**：微架构侧信道（共享 CPU 缓存等）只能通过调度隔离（敏感租户独占宿主）缓解、无法软件根除，本轮对其具体利用不做展开，等级 C；逻辑层授权 bug 仍是现实中更常见的泄露源。
- **验证方法**（待执行）：自建双测试租户，A 写唯一 canary 至其文件/快照/缓存/日志可见面，B 以全部正常 API 尝试读取；判据：全部不可见、尝试留痕。证据等级：方法 C，待自测（双租户 canary 应做成持续巡检而非一次性测试）。

### T17 凭证窃取（Credential Theft，沙箱内 / 经 Agent）

- **攻击前提**：AM-1/AM-2；凭证以某种形式进入了 Agent 可达域：环境变量、配置文件、工作区文件、进程内存、日志、LLM 上下文（system prompt/工具返回中夹带）。
- **攻击面**：env 与 `/proc/*/environ`、`.git-credentials`/云 CLI 配置、工具返回未脱敏、模型上下文回显（对应 OWASP LLM02:2025 Sensitive Information Disclosure 与 LLM07:2025 System Prompt Leakage 的治理范畴，等级 A/B）；窃取后外带通道为 T09/T12。
- **信任边界**：TB-1（上下文即攻击面，是 Agent 系统特有）、TB-5、TB-4（外带）。
- **影响**：用户/平台的 API Key、云凭证、仓库权限被复用至沙箱外（凭证一旦外带，沙箱边界不再相关）；长期凭证危害远大于任务期。
- **预防**：凭证不进沙箱、不进上下文：由 Harness 侧代理注入（工具在沙箱外以凭证执行、只回结果）或下发短时、单任务、最小 scope 的临时凭证；env 注入改为按需文件挂载 + 任务结束即焚；工具返回与日志做密钥模式脱敏；长期凭证永不下发。
- **检测**：出站流量/模型输出中的密钥模式扫描（DLP 式）；凭证使用侧审计（云/API 提供方的调用来源与时间异常）。
- **缓解与恢复**：以「已外泄」为默认假设轮换涉事凭证、吊销会话、回溯凭证使用日志。
- **剩余风险**：任务本身需要用的凭证（如让 Agent 推代码的仓库 token）在任务期内可被滥用，只能靠短时+最小 scope+审计压缩窗口；模型上下文中的隐性敏感信息（非密钥格式）难以模式化脱敏。
- **验证方法**（待执行）：自建任务植入假凭证（格式真实、前缀标记为测试、不可用），分别放 env/文件/上下文，诱导测试 Agent 做正常任务并监测外带通道与输出；判据：假凭证未出现在任何出站请求/跨任务日志中，或出现即触发脱敏告警。证据等级：方法 C。

### T18 浏览器 Cookie / Session / Token 窃取

- **攻击前提**：AM-1/AM-2；浏览器沙箱中存在已登录会话（用户 Cookie、localStorage、已保存密码），且 Agent 能读页面内容、执行 JS、访问浏览器 profile 目录或下载文件。
- **攻击面**：Chromium profile 存储、CDP（Chrome DevTools Protocol）调试接口（可导出 Cookie、执行任意页面脚本）、扩展、页面内同源策略外的数据（跨站请求中的会话）、浏览器同步数据。Chromium 自身有进程沙箱与站点隔离（官方设计文档，等级 A，见 §1.27），但那防的是网页攻浏览器，不防「操作浏览器的 Agent 读会话」——此区分必须写清，避免误引。
- **信任边界**：TB-8、TB-6（浏览器集群跨用户复用时）。
- **影响**：用户在目标站点的会话被劫持（绕过密码与 MFA 的会话级接管）、以用户身份在站点内操作、连带 SSO 可达的其他站点风险。
- **预防**：浏览器会话按任务/用户独占 profile、用后销毁（含 Cookie 与存储的彻底清理）；CDP 端口仅控制端可达且强认证、绝不暴露给沙箱内代码或公网；敏感站点用独立会话容器；会话材料不落共享存储；下载/上传经策略网关（见 T25）。
- **检测**：CDP 连接审计、profile 目录访问监测、Cookie 导出类 API 调用告警、会话在异地/异 UA 的使用（站点侧信号，平台侧有限）。
- **缓解与恢复**：销毁会话并通知用户在目标站点登出全部会话/轮换密码；封禁涉事任务与租户。
- **剩余风险**：Agent 完成任务本就需要「以登录态操作页面」，会话可用性与防窃取是同一枚硬币：能操作即能滥用操作权，只能靠任务级授权范围、操作审计与会话短命缓解。
- **验证方法**（待执行）：自建测试站点发放标记 Cookie，在自建浏览器沙箱中以普通任务权限尝试经 JS、文件系统、CDP 三路读 Cookie（HttpOnly 场景与非 HttpOnly 场景分开记录）；判据：与设计声明一致（声明不可读的路径确实不可读）、CDP 外部不可达。证据等级：方法 C。

### T19 Prompt Injection 导致的越权工具调用

- **攻击前提**：AM-1；不可信内容（网页、邮件、文件、仓库、工具返回）进入 LLM 上下文并包含指令性文本，模型把数据当指令执行。对应 OWASP LLM01:2025 Prompt Injection（等级 A/B，§1.27）；OWASP 亦明确提示尚无万无一失的防注入方法（该表述等级 B，本轮经二手来源转述，Round 2 应回 OWASP 原文核对）。
- **攻击面**：TB-1 全线：检索内容、浏览器页面、代码注释、commit 信息、图片 OCR 文本、MCP 工具返回等一切进上下文的数据。
- **信任边界**：TB-1 → TB-2（注入的危害在工具调用落地的瞬间兑现）。
- **影响**：以 Agent 被授予的权限执行攻击者意图：读文件、发请求、改数据、调工具；影响上限 = Agent 权限上限（与 T20 叠加）。
- **预防**：**按「注入必然成功」做设计**：工具层做与模型无关的确定性授权（能力白名单、参数约束、敏感动作人工批准/策略引擎裁决）；上下文分层与来源标记仅作辅助；高危工具（发送、删除、支付、凭证相关）默认需带外确认；Agent 权限最小化（见 T20）。
- **检测**：工具调用序列异常（读敏感资源后紧接外发）、注入特征内容与后续高危调用的关联告警、canary 指令植入巡检（在测试内容中埋唯一指令词，观察是否被执行）。
- **缓解与恢复**：中断任务链、回滚已执行的可逆操作、按工具日志圈定影响、轮换被触及凭证。
- **剩余风险**：这是当前公认的未解决问题：过滤/对齐只能降概率，确定性授权边界才是底线；底线之内的低危工具滥用（骚扰性调用、额度消耗）仍难完全避免。
- **验证方法**（待执行）：自建测试页/文档埋无害 canary 指令（要求 Agent 调用一个只记录不执行的哨兵工具），在自有 Agent 上跑任务；判据：哨兵工具未被调用，或调用在策略层被拦并告警；重复多轮统计拦截率（只报自测口径，不外推）。证据等级：方法 C，待自测。

### T20 合法工具组合突破权限边界（Excessive Agency / Confused Deputy）

- **攻击前提**：AM-1/AM-2；单个工具各自合规，但组合后越界：如「读文件」+「发 HTTP 请求」= 数据外带；「查数据库」+「发消息」= 跨用户数据泄露。Agent 持有超出任务所需的权限/工具/自主度，对应 OWASP LLM06:2025 Excessive Agency（等级 A/B）。
- **攻击面**：工具注册表与权限授予面：过宽的工具 scope、长期有效的工具授权、无金额/范围/对象上限的动作型工具、跨工具共享的上下文与凭证。
- **信任边界**：TB-2；本质是授权模型粒度不足，而非任何单点漏洞。
- **影响**：在不触发任何漏洞检测的情况下完成越权数据访问、外带或破坏性操作；审计上每一步「都合法」，事后定责困难。
- **预防**：按任务动态授予最小工具集与最小参数域（对象、金额、域名、行数上限）；数据流策略：标记敏感数据源与外发 sink，策略引擎阻断「敏感源 → 外部 sink」的组合（信息流控制思路，等级 C，为设计建议非既成标准）；高影响动作分级批准；工具授权短时化、任务结束即收回。
- **检测**：跨工具数据流审计（taint 式追踪：敏感读取与外发在同一任务内共现即告警）；工具组合模式基线。
- **缓解与恢复**：收紧该类任务的工具集与数据流策略、回滚组合动作的影响、复盘授权模板。
- **剩余风险**：信息流策略必然与业务灵活性冲突（很多正常任务就是「读数据再发出去」），只能按数据敏感度分级，不能一刀切；组合空间随工具数指数增长，枚举式防御不完整。
- **验证方法**（待执行）：自建双工具哨兵场景（A 工具能读含 canary 的测试数据、B 工具能向自有回显服务发送），分别在有/无数据流策略下跑测试任务；判据：无策略时 canary 到达回显服务（证明风险真实存在）、有策略时被阻断并告警——前后对照即证据。证据等级：方法 C（对照设计见 §2.6）。

### T21 恶意子进程与后台任务（驻留 / 脱缰进程）

- **攻击前提**：AM-2；沙箱内代码可 fork、双 fork 守护化、写 cron/systemd 单元（guest 内）、开机/会话恢复钩子，或平台超时/取消只杀主进程不杀进程组。
- **攻击面**：进程树与生命周期管理：exec API 的进程回收语义、cgroup 进程枚举、暂停/恢复与快照（进程状态可能随快照复活，见 T23）。
- **信任边界**：TB-3 内侧 + 生命周期边界（任务结束 ≠ 进程结束，除非平台证明之）。
- **影响**：任务「结束」后继续运行（挖矿、对外攻击、等待回连）、污染复用环境（T24）、逃避按任务计费与审计（审计以任务为单位时后台进程成盲区）。
- **预防**：以 cgroup 为回收单位（销毁时杀整个 cgroup 并核验为空）；PID namespace 随 init 退出全量回收；禁止或受控的持久化钩子（cron 等在一次性沙箱中无意义即禁用）；执行超时用进程组/cgroup 级 kill 而非单进程信号。
- **检测**：销毁后宿主侧核验（cgroup.procs 为空、端口/文件句柄释放）；沙箱内进程数与父子关系异常（脱离原进程树的进程）监测；空闲沙箱的 CPU/网络活动告警。
- **缓解与恢复**：强制销毁整个环境而非单进程、复查同批次环境是否存在同类驻留、封禁涉事租户模式。
- **剩余风险**：长驻型工作空间（按用户常驻）中「合法后台任务」与「恶意驻留」不可分，只能靠资源配额（T22）与行为审计约束；快照恢复可能合法地复活进程，需在产品语义上明确。
- **验证方法**（待执行）：自建沙箱内以无害方式启动一个会双 fork 并周期写心跳文件的测试进程，任务结束后检查：进程是否存活、心跳是否继续、cgroup 是否为空；判据：销毁后全部归零。对应评测指标 C4（§2.4）。证据等级：方法 C，待自测。

### T22 资源耗尽与拒绝服务（Resource Exhaustion / DoS）

- **攻击前提**：AM-2/AM-3；任一资源维度未设限或限而不严：CPU、内存、PID 数（fork bomb）、磁盘与 inode、网络带宽与连接数、文件句柄、控制平面 API 频率、LLM/工具调用次数（对应 OWASP LLM10:2025 Unbounded Consumption，等级 A/B）。
- **攻击面**：guest 内资源、宿主共享资源（内存带宽、磁盘 IOPS、网络出口）、控制平面（创建风暴）、计费面（他人付费的资源被消耗，即「钱包耗尽」变体）。
- **信任边界**：TB-3（cgroup/配额面）、TB-6（吵闹邻居）、控制平面限流面。
- **影响**：同宿主/同池租户性能受损或不可用；平台成本被恶意放大；极端时宿主 OOM 误杀无辜进程、节点宕机。
- **预防**：全维度配额（CPU/内存/PID/disk/inode/fd/带宽/连接数/任务时长/并发数）且默认值取保守；cgroup v2 的 memory.max、pids.max、io 限额等机制（等级 A，内核官方文档范畴，本轮未逐项引页，Round 2 补）；创建与 API 限流；租户级预算与熔断；OOM 策略保证「谁超限杀谁」。
- **检测**：配额命中率、宿主级资源水位与 top offender 租户视图、创建速率异常、单任务成本异常告警。
- **缓解与恢复**：限流/冻结涉事租户、驱逐超限沙箱、扩容或调度迁移受影响租户。
- **剩余风险**：未被建模的资源维度总会出现（历史经验如此，等级 C 判断）；合法重负载任务与攻击在形态上重叠，阈值是可用性与安全的持续权衡。
- **验证方法**（待执行）：自建沙箱内逐项施加无害压力（CPU 忙循环、受控内存增长、受控进程派生、受控写盘），观测限制是否在配额点生效且邻居哨兵任务性能不受显著影响；判据：见指标 C1–C3 的通过线（§2.4）。**禁止**在共享/生产环境做此验证。证据等级：方法 C，待自测。

### T23 恶意快照 / 模板污染（Snapshot & Template Poisoning）

- **攻击前提**：AM-3/AM-4；平台支持用户保存/分享快照与模板，或快照恢复代码解析不可信快照文件；或攻击者先在环境中植入后门再将其固化进快照/模板供后续（自己或他人）恢复。
- **攻击面**：快照格式解析器（内存快照反序列化是 VMM 的高危解析面，见 T05）、快照中的文件系统与进程状态、模板市场/共享机制、快照中的随机数状态与密钥材料（恢复后多实例共享同一随机状态/主机密钥是快照技术的经典陷阱，等级 B，Firecracker 官方快照文档有相关注意事项，Round 2 回原文核对后升 A）。
- **信任边界**：TB-5、TB-7。
- **影响**：后门随模板扩散至大量环境；克隆实例间密钥/随机数重复导致密码学失效；恶意快照触发 VMM 解析漏洞可升级为 T05。
- **预防**：快照/模板按代码制品管理（签名、来源、扫描、版本）；恢复时重生成机器身份、主机密钥与随机种子；用户快照默认私有、分享需显式动作；快照解析在最小权限进程中完成。
- **检测**：模板内容扫描与 SBOM/文件 diff 巡检；同源快照恢复出的多实例出现相同主机密钥/相同随机指纹的自动检测。
- **缓解与恢复**：下架污染模板、按模板血缘圈定并重建全部派生环境、轮换克隆共享过的密钥。
- **剩余风险**：快照内「休眠状态」的完整审计成本极高（内存态几乎不可审）；跨版本快照兼容解析的攻击面长期存在。
- **验证方法**（待执行）：自建环境在快照前植入无害标记进程与标记文件、预置固定测试密钥，恢复出两个实例后比对：标记状态按产品声明存活/清除、两实例机器身份与密钥是否已分化；判据：与声明一致且身份已分化。对应指标 C6。证据等级：方法 C。

### T24 环境复用 / 预热池状态污染（Warm Pool Reuse Contamination）

- **攻击前提**：AM-3；平台为降延迟复用环境（预热池回收已用实例、长驻工作空间转租、浏览器实例复用），且回收清理不彻底。
- **攻击面**：残留面清单：文件系统残留、进程残留（T21）、内存残留、shell 历史/缓存/包缓存、浏览器 profile 残留（T18）、/tmp 与交换分区、环境变量与挂载残留。
- **信任边界**：TB-5、TB-6；这是「性能优化与隔离」的直接冲突点，必须与评测 A 组（启动延迟）联动评估，不能只看速度。
- **影响**：下一租户读到上一租户数据/会话（等同 T16 的一种实现路径）；上一租户植入的后门在下一租户环境内执行。
- **预防**：最稳妥策略是敏感等级场景不复用（用后即毁，以快照/预热未用实例换速度）；确需复用时，复用单位降级为「未被租户使用过的预热实例」，已用实例只回收资源不回收状态；清理流程须有可验证清单 + 复用前 canary 巡检（见 T16 验证法常态化）。
- **检测**：复用前自动化残留扫描（文件/进程/挂载/profile 多维 canary）；租户侧「我在环境里发现了不属于我的东西」的举报通道与抽检。
- **缓解与恢复**：立即停用复用池、销毁全部待复用实例、按复用记录圈定可能受影响的租户对并通知。
- **剩余风险**：清理清单永远可能漏项（新的缓存位置随软件版本出现）；「清理完成」缺乏密码学级证明，只能靠持续 canary 巡检逼近。
- **验证方法**（待执行）：自建复用池，租户 A 在环境中按残留面清单逐项植入 canary，走完平台回收流程分配给租户 B，B 侧逐项核查；判据：canary 命中数为 0，任一命中即该复用策略不合格。对应指标 C5。证据等级：方法 C，待自测。

### T25 浏览器 / GUI 特有风险（恶意下载、剪贴板、上传与桌面通道）

- **攻击前提**：AM-1/AM-2；Agent 操作浏览器/桌面：可下载文件、读剪贴板、上传文件、经远程桌面（VNC/RDP 类）与用户侧交互。
- **攻击面**：下载目录（恶意文件落盘后被其他通道打开/执行）、剪贴板双向同步（用户侧敏感内容被页面/脚本读取，或恶意内容写入用户剪贴板）、文件上传选择器（页面诱导上传沙箱外/用户文件）、桌面会话的驱动器/打印机/USB 重定向、截图/录屏通道（画面含敏感信息并进入 LLM 上下文，叠加 TB-1）。
- **信任边界**：TB-8。
- **影响**：恶意文件向用户设备/下游系统传播；用户剪贴板与本地文件泄露；截图中的凭证/隐私进入模型上下文与日志（长期留存风险）。
- **预防**：下载隔离区 + 类型策略 + 扫描，下载物不自动在任何宿主/用户设备执行；剪贴板默认单向或关闭、放行需用户显式动作且内容审计；上传仅限工作区白名单目录；远程桌面重定向默认全关按需开；截图进上下文前做敏感区域策略（产品相关，等级 C）。
- **检测**：下载文件哈希与情报比对、剪贴板通道启用与流量审计、上传路径审计、截图留存策略合规检查。
- **缓解与恢复**：隔离下载物、终止会话、提示用户更换可能经剪贴板泄露的凭证、删除留存截图。
- **剩余风险**：Computer Use 的本质是「看屏幕 + 操作」，画面敏感信息暴露只能降分辨率/降留存，不能归零；剪贴板与可用性（复制粘贴是刚需）的冲突长期存在。
- **验证方法**（待执行）：自建浏览器沙箱放置无害测试下载文件（EICAR 类标准测试文件思路，仅用公开的无害测试签名文件，等级 B）与剪贴板 canary 文本，验证下载策略与剪贴板隔离的实际行为与产品声明是否一致；判据：行为与声明逐项一致、偏离项有告警。证据等级：方法 C。

## 2. 任务二：可复现 Benchmark 评测体系设计（只设计，不含任何实测数字）

### 2.0 总原则

1. **先定义，后测量**：每个指标先给出可计算的精确定义（起止事件、公式、单位），定义不清的指标不测。
2. **不编造数字**：本节所有阈值位置留空或写作「待预实验标定」；凡引用外部数字，必须按 §2.7 标注来源类型。
3. **可复现优先于规模**：宁可小样本但全量公开环境指纹与原始数据，不做不可复现的大样本宣传数。
4. **冷/热、成功/失败分开统计**：失败样本不得静默丢弃（见 §2.5）。
5. **SaaS 黑盒与自托管白盒分轨**：商业 SaaS 只能测 API 可观测面，禁止把黑盒推测写成其内部实现结论；两轨结果不得混排成一张「总排名」。

### 2.1 测量学规范（全组通用）

- **时钟**：单机内延迟用单调时钟（monotonic clock）；跨机延迟用同一测量端打时间戳（请求发出/响应收齐均在客户端计时），不比较两台机器的墙钟。所有原始记录保留原始时间戳与时钟来源说明。
- **计时边界**：API 类延迟一律拆三段记录：`t_submit`（客户端发出请求前）、`t_ack`（控制平面确认/返回 ID）、`t_ready`（可执行探针首次成功，见 A1）。不得只报其中一段并称之为「启动时间」。
- **就绪探针（ready probe）**：统一定义为「在沙箱内执行一条无业务语义的探针命令并校验其标准输出等于约定 canary 值」。探针本身的开销须先在对照组 G0 上标定并在报告中披露。
- **样本量下限（设计值，非结果）**：延迟类指标每（系统 × 场景）组合有效样本 n ≥ 100 方可报 P95，n ≥ 300 方可报 P99（理由见 §2.5 的分位数口径）；达不到时只报实际 n 与已达到的最高分位，并明确标注。可靠性类指标（C 组）每用例重复次数在用例定义中单独规定。
- **预热与漂移控制**：测量顺序随机化/交错执行（interleaving，见 §2.6）；每批次开始前记录宿主机负载、邻居情况；批次中插入 G0 基线复测，基线漂移超过预实验标定范围时整批作废重测并记录原因。
- **环境指纹（每次运行必填）**：宿主机（CPU 型号/核数、内存、磁盘类型、内核版本、是否独占）、运行时与版本（运行时二进制版本/digest）、镜像/模板 digest、配额参数（vCPU/内存/磁盘/网络限额的设定值）、区域与网络位置（自托管记拓扑，SaaS 记区域与套餐档位）、并发背景（同宿主其他负载有无）、测量端位置与版本、日期与 retrieved_at。
- **原始数据**：保留逐样本原始记录（CSV/JSONL），汇总表必须可由原始数据脚本化重算；报告只引汇总值时须同时给出原始数据存放路径。

### 2.3 B 组：运行性能（8 条）

通用前提：所有 B 组指标都以「相对开销」为主报告形式：`overhead = (被测系统结果 − G0 基线结果) / G0 基线结果`，绝对值与基线绝对值同时给出；工作负载版本、参数、数据集规模全部固定并写入复现包（§2.8）。工作负载只用公开可得的标准负载或自研开源脚本（脚本须随报告发布），不在此预设任何预期数值。

|---|---|---|---|---|
| B1 | 单线程 CPU 相对性能 | 固定 CPU 密集负载（纯计算、无 IO）的完成时间相对 G0 的比值；负载须为确定性指令流（禁用依赖时间的负载） | 比值（无量纲）+ 绝对秒数 | 同一二进制/脚本、单线程绑核条件一致；多轮取中位数并给离散度 |
| B2 | 多线程扩展性 | 同一并行负载在 vCPU 数逐档增加时的吞吐曲线（吞吐 vs vCPU 数），报告曲线而非单点；以相对 G0 同档曲线对比 | 吞吐单位随负载定义 | 档位与配额 vCPU 一致；超配额的档位不测（测了也只是配额墙） |

| B4 | 磁盘顺序 IO 吞吐 | 固定块大小、固定队列深度、直写绕缓存口径下的顺序读/写吞吐，相对 G0（同盘直测）比值；缓存口径（page cache 是否参与）必须声明，未声明的结果无效 | MiB/s + 比值 | 读写分开；临时盘与持久卷分开测；盘类型写入环境指纹 |
| B5 | 小文件/元数据性能 | 固定数量小文件的创建+写入+读取+删除全程耗时（或 ops/s），相对 G0 比值；文件数与单文件大小预先固定 | ops/s + 比值 | 与 B4 分开（元数据路径与数据路径在 OverlayFS/gVisor/MicroVM 下差异最大，正是本条的测量目的） |
| B6 | 网络延迟与吞吐 | 两段分别测：①沙箱↔同宿主/同可用区固定对端 RTT（P50/P95/P99，口径同 §2.5）；②沙箱→经 egress 路径到固定外部对端的吞吐；对端必须自有可控（自建对端服务器），不得用公共测速站点的不可控结果作正式数据 | ms；Mbit/s | 直连与经代理两条路径分开；外部段只作参考轨并标注网络不可控因素 |

| B8 | 长任务稳定性 | 固定负载持续运行至声明时长（如以小时计的档位，时长预先声明）：吞吐随时间的漂移（分时段中位数曲线）、错误/重启次数、内存占用随时间曲线（查泄漏） | 漂移 %；次；MiB 曲线 | 时长未达声明值即中断的运行作废并记录原因；与 C 组联动（期间的配额事件一并记录） |

### 2.4 C 组：隔离与可靠性（8 条）

通用形式：每条是「用例集 + 通过判据 + 通过率/误差量」的合规型指标，不测速度。通过线（阈值）在预实验后、正式测量前冻结并写进复现包，禁止测后改线。用例全部无害化（canary/哨兵/自有对端），与 §1 各条验证方法一一对应。

| ID | 指标 | 精确定义 | 单位/形式 | 对应威胁与通过判据要点 |
|---|---|---|---|---|

| C2 | 内存配额与 OOM 行为正确性 | 受控内存增长下：限制在配额点生效、被 OOM 终止的是超限任务自身（而非邻居/宿主进程）、终止后内存完整回收，三项各记通过/失败 | 通过率（分项） | T22；增长步长与速率预先固定；宿主侧全程监测，出现宿主级 OOM 即整例失败 |

### 2.5 统计口径（P50/P95/P99 与结果呈现规范）

- **分位数定义**：统一采用 nearest-rank 法：对升序样本 `x[1..n]`，P_k 取 `x[ceil(k/100 × n)]`。报告中禁止混用插值法而不声明。
- **最小样本与可报分位**：n < 100 只报中位数（P50）与最大值；100 ≤ n < 300 可报至 P95；n ≥ 300 方可报 P99。此为设计规则（防止小样本 P99 实为最大值冒充分位数），在报告中须连同每组实际 n 一起呈现。
- **必报五元组**：每项延迟指标报告 `(n, P50, P95, P99, max)`，并附失败数与失败率；只报单一均值或单一分位的结果视为不合格数据。
- **均值的使用限制**：延迟类不以均值作主指标（长尾被掩盖）；吞吐/成本类可用均值，但须同时给中位数与离散度（IQR 或标准差，二选一并声明）。
- **失败样本处理**：超时、创建失败、状态不一致等失败样本**不进**延迟分位计算，但必须计入失败率并单列；禁止重试后只取成功样本而不报重试次数（重试策略如启用须预先声明且原始失败留痕）。
- **置信与波动**：同条件重复批次 ≥ 3 批，报告批间波动；两系统差异小于批间波动时，结论写「在当前测量精度下不可区分」，禁止硬排名次。
- **异常值**：不删除。怀疑为宿主干扰的样本可标记并附敏感性分析（含/不含各一份），但正式结论以全量为准。
- **图表**：延迟类优先给 CDF 或分位表，不给只有柱状均值的图；时间序列类（B8）给原始曲线不平滑掩盖。

### 2.6 对照组设计

| 组 | 定义 | 角色 |
|---|---|---|
| G0 | 宿主机原生进程（无任何沙箱层），同机同负载 | 性能基线（B 组相对开销的分母）；不是安全对照 |
| G1 | 原生容器（runc，默认配置） | 容器路线基线 |
| G2 | 加固容器（runc + 基线加固：cap drop、no-new-privileges、seccomp、只读根、user namespace） | 测「加固的性能代价」与 C 组差异，配置清单须公开 |
| G3 | gVisor（runsc，官方默认收敛配置） | 安全容器路线 |
| G4 | MicroVM（Firecracker + jailer，按官方 prod-host-setup 基线） | MicroVM 路线；Kata 若测则单独成组 G4b，配置与 Firecracker 不可混 |
| G5 | Wasm（Wasmtime，WASI 最小授权） | 仅测其可运行的负载子集；不可运行的负载记 N/A 并说明原因，**禁止**以子集成绩外推全负载结论 |
| G6 | 商业 SaaS（黑盒轨） | 只测 API 可观测指标（A 组、B6 外部段、D 组账单面、C8 中可从客户端验证的子集）；单独成轨报告，与自托管组不混排总分 |

**公平性规则**：①同组对比须同宿主（或同等规格）、同镜像/rootfs 内容、同配额设定值、同负载版本；②执行顺序交错随机化，避免「先测者占缓存、后测者遇漂移」；③每组测前统一预热规则（测冷启动的 A1 除外，其预热状态按定义清零）；④任何一组用了不同参数（如更大内存）须在结果表中显式标注，该行退出横比；⑤浏览器/GUI 负载为独立子轨（负载与指标 A/B 的子集复用），不与无头代码执行轨混排。

### 2.7 成本模型（D 组，8 条）

计价通则：自托管轨用「资源量 × 声明单价」与「云账单实测」二选一并声明，单价来源（云厂商公开价目页）须记 URL 与 retrieved_at；SaaS 轨只用其公开价目与实际账单，禁止用自托管单价替 SaaS 估算内部成本。所有成本指标必须同时给出「资源量口径」（如 sandbox-hour、GiB-month）与「金额口径」，只给金额不给资源量的数据不可复现、视为不合格。

| ID | 指标 | 精确定义（公式） | 单位 | 要点 |
|---|---|---|---|---|
| D1 | 空闲成本 Idle Cost | 就绪空载沙箱保持 1 小时的总成本 / 沙箱数（自托管：其占用的预留资源折算；SaaS：按其计费规则的空闲时段账单） | 金额/sandbox-hour + 资源量 | 空载定义同 B3；与 B3 联动（内存开销是空闲成本主项的假设须由数据验证，不预设结论） |
| D2 | 创建-销毁固定成本 | 单个沙箱全生命周期中与运行时长无关的成本：创建/销毁阶段消耗的控制面与宿主资源折算（SaaS 轨如无此项计费则记 0 并注明计费结构差异） | 金额/沙箱 | 与 A1/A7 的资源占用记录联动；不得把运行时成本重复计入 |
| D3 | 单任务成本 Cost per Task | 标准任务集（§2.8 定义的固定任务套件）跑完后的总账单/资源成本 ÷ 成功任务数；失败任务消耗计入分子（真实成本口径） | 金额/成功任务 | 任务套件版本固定；同时报「含失败」与「仅成功消耗」两口径，主口径为含失败 |
| D4 | 每千次任务成本 | D3 × 1000 的归一化表达，但在声明的并发档位下实测（不许可用单任务成本线性外推代替高并发实测，二者都报并标注差异来源） | 金额/1000 任务 | 并发档位同 A8；线性外推值如给出须标 [ESTIMATE] |
| D5 | 单活跃用户成本 | 给定用户行为画像（每用户每日任务数、平均任务时长、并发峰值、数据留存量——画像参数预先声明并版本化）下一个计费周期的总成本 ÷ 活跃用户数 | 金额/用户/周期 | 画像是假设，必须标 [ESTIMATE] 并给参数表；不同画像分别成行，禁止只挑最有利画像 |
| D6 | 预热池待机成本占比 | 预热池待机资源成本 ÷ （预热池 + 实际执行总成本）；与 A2 的延迟收益联动呈现（成本换延迟的交换曲线，而非孤立数字） | % + 金额 | 池规模为自变量逐档报告；无预热机制记 N/A |
| D7 | 快照与持久化存储成本 | 单位 GiB-月存储成本 + 单次快照创建/恢复的折算成本（与 A3/A4 联动）；含快照留存策略（份数/天数）声明 | 金额/GiB-月；金额/次 | 自托管记存储介质与冗余方式；SaaS 记其存储计费项原文出处 |
| D8 | 平台固定开销分摊 | 控制平面、日志/审计、监控、egress 代理等共享组件的周期成本 ÷ 同期 sandbox-hour 总数，得每 sandbox-hour 的固定开销分摊 | 金额/sandbox-hour | 只在自托管/私有化轨测；组件清单须列明，缺项（如未计日志存储）须显式声明 |

### 2.8 标准任务套件与数据来源标注规范

**标准任务套件（设计，版本 v0.1 待 Round 2 冻结）**：ST-1 空任务（创建→探针→销毁，测纯生命周期）；ST-2 纯计算任务（固定算法脚本，测 B1/D3）；ST-3 工具链任务（固定小项目的依赖安装+测试运行，测真实 Agent 常见负载，依赖源须镜像化以消除公共仓库波动）；ST-4 文件密集任务（固定规模文件生成/读写/打包）；ST-5 网络任务（仅访问自有对端服务的固定请求集）；ST-6 浏览器任务（子轨，固定页面集位于自有站点）。每个套件须含：输入、步骤、成功判据、资源配额、预期产物校验（哈希/内容校验，防「假成功」）。

**数据来源标注（强制四标签，任何数字入报告必带）**：

| 标签 | 含义 | 必带字段 |
|---|---|---|
| `[OFFICIAL]` | 厂商/项目官方公布（文档、价目页、博客、论文中的官方数据） | URL、发布日期、retrieved_at、适用版本/规格原文摘录；官方数据只证明「官方如此宣称」，引用时措辞为宣称值 |
| `[THIRD-PARTY]` | 独立第三方实测（论文、公开 benchmark 仓库、可复现的第三方报告） | 作者/机构、URL、其环境与方法摘要、retrieved_at；方法不可复现者降级为参考，不进对比表 |
| `[SELF]` | 本项目按本节规范自测 | 复现包路径（§2.9）、环境指纹、原始数据路径、批次与 n |
| `[ESTIMATE]` | 基于声明假设的推算 | 全部假设与参数、计算式、敏感性说明；不得与实测值同表同列混排，视觉上须可区分 |

**禁止事项**：禁止把 [OFFICIAL] 宣称值写成「实测表明」；禁止把不同标签的数据算进同一个平均值；禁止引用无 URL、无日期的「网上数据」；价格类 [OFFICIAL] 数据超过一个复核周期未重验的，引用时加「可能已过期」标注（复核周期由主线在 COVERAGE 中统一规定）。
